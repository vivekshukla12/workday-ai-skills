# First customer-style pilot

This is an exercise procedure, not a populated test case. No tenant inputs, sample-run records or results belong in the public repository.

## Start in a fresh chat

Use the installed skill and bundled blank workbook. Do not require GitHub access or prior development conversation. State the installed skill version. Ask whether the user is running an exercise or live planning, which aggregate scope and horizon to use, and whether the data is permitted for processing in the selected environment.

Provide the blank workbook and explain Start Here first. If the customer already has a completed workbook, inspect it and ask only about missing material information. Do not require every sheet to be filled. Prism is optional for this pilot.

## First scenario

A temporary location-unavailability scenario is a useful first exercise, subject to user selection. Start with a small aggregate workforce population, customer service requirements and independent workforce controls where available. Add skills, operations and finance only when needed for the requested conclusions.

Business minima and off-site capability must be supplied or explicitly approved as exercise assumptions. They are not standard Workday workforce fields. Keep demo observations and hypothetical assumptions distinguishable.

## Execute and review

1. Validate the baseline and explain any scoped blockers.
2. Propose a short list of evidence-supported scenarios, including any customer request.
3. Review one scenario and its required assumptions. Agree indicative versus final exercise output.
4. Capture a private run snapshot, execute the calculations and show the arithmetic behind the key gap.
5. Compare with a small independent calculation agreed for the exercise. Correct discrepancies before treating the pilot as successful.
6. Let the user revise Current Value in the same assumption row. Reconfirm approval, create a new Run ID and show changes from the earlier run.
7. Propose mitigations, obtain explicit exercise decisions, and build a timeline from user-supplied scheduling inputs.

## Acceptance criteria

- Headcount/FTE controls reconcile where independent evidence exists; untested checks are visible.
- Vacancies are not subtracted from filled FTE. Leave and scenario losses are counted once.
- Unknown or suppressed values do not become zero. Zero requirements do not cause division errors.
- Shared pools and repeated skill rows do not multiply workforce supply or minima.
- Financial conclusions appear only when their prerequisites exist.
- AI assumptions are disclosed; unauthorized assumptions do not drive final results.
- Changing an assumption yields an explainable new result and preserves the earlier snapshot.
- Exercise approvals do not authorize live actions.
- Inputs, outputs and feedback containing tenant detail remain outside the repository.

Record the pilot outcome privately as Passed, Needs correction or Not tested for each applicable criterion. A technical skill validation is not evidence of an end-to-end customer pilot.
