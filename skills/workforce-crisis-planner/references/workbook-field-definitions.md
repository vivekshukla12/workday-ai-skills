# Workbook sheet and field definitions

This reference records approved design decisions for the customer crisis-simulation intake workbook. Use it when explaining fields, assessing necessity, or revising the template. A field remains provisional until its sheet walkthrough is approved.

## Workbook-wide data-minimization and sensitivity standard

For every requested field, establish why the simulation needs it, whether the customer is reasonably expected to have it, and whether aggregated non-identifying data can support the same analysis.

Use this order of preference:

1. Aggregated, non-identifying data.
2. Anonymous data, only when re-identification is not reasonably possible.
3. Pseudonymous data when authorized record linkage is necessary. Treat it as personal data, not anonymous data.
4. Identifiable or sensitive data only when legally or operationally indispensable, with a documented purpose, approval, restricted access, and retention rule.

Every input column must be classified and visually identified as:

- **Required:** needed for the standard simulation.
- **Conditionally required:** needed only when the stated scenario or analysis is in scope.
- **Optional sensitive:** provide only when necessary and after the appropriate approval.
- **Calculated:** generated by the workbook or agent; the customer must not populate it.

Highly sensitive or commercially confidential fields must be optional by default, visibly highlighted in the input sheet, and accompanied by help text explaining when they are needed. Customers must leave them blank when the relevant scenario or analysis is outside the agreed scope.

Do not request employee names, personnel numbers, email addresses, raw health or absence details, protected characteristics, free-text personnel notes, credentials, Workday tenant names or URLs, or customer identifiers unless a later approved requirement explicitly establishes necessity and governance.

## Sheet 1 — Start Here

**Status:** Approved.

**Purpose:** Establish submission identity, time scope, calculation conventions, governance approvals, and calculated readiness without identifying the customer or Workday tenant.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Assessment ID | Required | Neutral submission code. Prohibit customer, tenant, or legal-entity names. |
| Version | Required | Revision number for traceability and correction history. |
| As-of Date | Required | Latest date represented by the submitted data. |
| History Start | Calculated | Derive from the earliest applicable historical record; do not request duplicate entry. |
| Planning Horizon End | Required | Last future period included in the simulation. |
| Base Currency | Required when financial amounts are in scope | ISO 4217 currency used for consolidated outputs. |
| Period Grain | Required | Default to Month; permit Week for short-duration operational crises. |
| Data-owner Approval | Required before simulation | Record status only; do not require the approver's name. |
| Privacy Review | Required before simulation unless formally exempt | Record status and, if needed, a non-sensitive approval reference. |
| Known Limitations | Optional | Record material limitations without names, individual cases, confidential narrative, or embedded extracts. |
| Readiness Checks | Calculated | Lock formula cells; do not run material conclusions until readiness conditions pass. |

No employee-identifying or special-category data is needed on this sheet.

## Sheet 2 — WD Workforce Extract

**Status:** Approved, except Off-site Capable FTE remains unresolved.

**Purpose:** Provide aggregated workforce supply using fields reasonably obtainable from Workday. Do not add non-Workday service assumptions to the extract.

**Row definition:** One aggregate workforce group for one period, entity when relevant, location, role, and Workday Worker Type. Multiple locations produce multiple rows. Never create one row per worker.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Row ID | Calculated | Generate automatically. |
| Period | Required | Month or week represented; Month is the default. |
| Entity Code | Conditional | Use for multi-entity scope or when entity differences affect the scenario. Permit a neutral code. |
| Location Code | Conditional | Support separate aggregate rows for relevant locations. Do not request addresses. |
| Role Code | Required | Use a governed Job Profile or Job Family mapping. Do not use Position ID or identifying business titles. |
| Worker Type | Required | Retain the Workday term and accept customer-configured values or an approved broader mapping. |
| Headcount | Required | Aggregate worker count. |
| FTE | Required | Aggregate full-time-equivalent capacity. |
| FTE on Leave | Conditional | FTE included in reported FTE but unavailable due to On Leave status on the reporting date. No leave type, dates, medical reason, or Worker ID. |
| Vacant FTE | Conditional | Approved position capacity currently unfilled, when reliable position data exists. |
| Off-site Capable FTE | Unresolved | Decide later whether it is reliably extractable or belongs in assumptions. |
| Scheduled Hours | Conditional extension | Exclude from the standard extract; add only for shift or short-duration hourly scenarios. |
| Total Base Pay | Optional sensitive | Aggregated amount only when role-level costing is necessary and Compensation access is approved. Never treat it as total employment cost. |
| Currency | Conditional | Include only when Total Base Pay is supplied. |
| Row Status | Remove | Final templates contain no sample rows; examples belong in help text. |

Apply a customer-approved minimum reporting-group threshold, preferably at least five workers. Suppress or combine smaller groups. Do not request names, Worker IDs, Position IDs, emails, protected characteristics, health details, absence reasons, performance or talent ratings, or personnel comments.

## Sheet 3 — Service Requirements

**Status:** Architecture approved; detailed refinement remains possible.

**Purpose:** Store customer-defined operational and continuity requirements that are not expected from Workday.

**Row definition:** One critical service, location scope, and required role combination. Use multiple rows where a service needs several roles or operates across locations.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Service Code | Required | Neutral identifier for a critical service; keep outside the Workday extract. |
| Location Scope | Conditional | Location where the requirement applies, or ALL when genuinely enterprise-wide. |
| Role Code | Required | Join to workforce supply through the governed role mapping. |
| Minimum FTE | Required | Lowest sustainable FTE for the service, role, and location. |
| Skill/Credential Code | Conditional | Critical verified skill, certification, or licence required by the service. |
| Minimum Qualified Headcount | Conditional | Minimum qualified people needed. |
| Minimum Qualified Backup Headcount | Conditional | Minimum qualified backup coverage needed. |
| Requirement Basis | Required | Neutral reference to an approved policy, continuity plan, SLA, exercise, or expert estimate. |
| Approval Status | Required before use | Requirement must be approved before driving material conclusions; do not require approver identity. |
| Capacity Allocation | Unresolved | Needed to prevent double-counting shared roles; decide later between percentage and Dedicated/Shared/Backup categories. |

Do not add Service Code to the WD Workforce Extract. Relate workforce supply to service demand through Role Code and Location Code.

## Sheet 4 — WD Critical Skills & Credentials

**Status:** Approved.

**Purpose:** Provide an aggregated point-in-time view of mandatory credentials and formally verified critical skills. Exclude the complete Workday skills inventory and general or self-declared skills from the first version.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Row ID | Calculated | Generate automatically. |
| As-of Date | Required | Date on which reported qualification coverage is valid. |
| Location Code | Conditional | Use when qualification availability is location-dependent. |
| Role Code | Required | Use the same governed mapping as WD Workforce Extract. |
| Skill/Credential Code | Required | Neutral code; do not request free-text worker descriptions or certificate numbers. |
| Record Type | Required | Verified Skill, Certification, or Licence. |
| Verification Basis | Conditional | Controlled category establishing validity; no worker assessment notes. |
| Qualified Headcount | Required | Aggregate count meeting the approved requirement. |
| Qualified Backup Headcount | Conditional | Aggregate formally available backups; no successor identities. |
| Credentials Expiring Within Horizon | Conditional | Aggregate count expiring before the planning horizon ends; no individual expiry dates. |
| Source Version | Dataset metadata | Store once rather than repeating per row. |
| Row Status | Remove | Use help text instead of sample records. |

Remove Service Code and Minimum Qualified to Service Requirements; remove Absence FTE and Open Positions as duplicates of workforce data; move Time to Fill and Notice Period to governed planning assumptions.

## Finance and Operations structure

**Status:** Approved.

These inputs are external financial or operational data even when a customer happens to use Workday Financial Management. Keep them separate from the WD workforce extracts.

### Financial Performance

**Row definition:** One period, version, entity when relevant, and financial planning unit.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Row ID | Calculated | Generate automatically. |
| Period | Required | Month by default. |
| Version | Required | Actual, Budget, or Forecast; never mix versions without identification. |
| Entity Code | Conditional | Use for multi-entity reporting. |
| Financial Planning Unit Code | Conditional | Governed cost center, business unit, profit center, or equivalent. Map to services separately where possible. |
| Revenue | Conditional | Aggregated revenue for the stated scope. Permit indexed or percentage values for screening. |
| Contribution Margin | Conditional | Use only when the customer already calculates it and supplies its definition; do not assume Gross Margin. |
| Aggregate Labor Cost | Conditional | Finance-defined total workforce-related operating cost. Prefer this over treating Workday Base Pay as complete cost. |
| Non-labor Operating Cost | Conditional | Aggregated non-workforce operating cost. |
| Currency | Conditional | Required with exact monetary values; derive from Base Currency when already converted. |

### Liquidity

**Whole section:** Conditional and highly sensitive. Complete only for liquidity or severe financial-crisis scenarios after Finance and Security approval.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Period | Conditionally required | Period represented. |
| Version | Conditionally required | Actual, Budget, or Forecast. |
| Entity Code | Conditional | Entity holding the liquidity. |
| Available Cash | Optional sensitive | Prefer runway band, percentage, or indexed value for screening. |
| Committed Liquidity | Optional sensitive | Prefer a band or percentage; exact facility data requires approval. |
| Minimum Required Liquidity | Conditional | Approved finance assumption. |
| Currency | Conditional | Required with exact monetary values. |
| Row ID | Calculated | Generate automatically. |

### Operational Capacity

**Row definition:** One period, version, location when relevant, and critical service.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Period | Required | Month by default; Week when a short-duration scenario requires it. |
| Version | Required | Actual, Budget, or Forecast. |
| Location Code | Conditional | Use when capacity is location-dependent. |
| Service Code | Required | Join to Service Requirements. |
| Capacity Unit | Required | Controlled unit such as transactions, cases, service tickets, operating hours, or production units. |
| Available Capacity | Required | Maximum available operational output for the period. |
| Expected Demand | Required | Expected demand in the same unit. |
| Minimum Service Demand | Conditional | Lowest acceptable demand coverage or service commitment. |
| Actual Output | Conditional | Actual delivered output. |
| Output per Available FTE | Calculated | Calculate rather than requesting duplicate customer entry. |
| Row ID | Calculated | Generate automatically. |

Support two confidentiality levels: Screening Mode uses indices, percentages, ranges, or risk bands by default; Detailed Mode uses exact amounts only when necessary and approved.

## Critical Dependencies

**Status:** Approved.

**Whole sheet:** Conditional. Complete only when supplier, customer, technology, site, utility, transport, regulatory, or related dependency scenarios are in scope.

**Row definition:** One dependency affecting one critical service and, where relevant, one location. Use multiple rows when one dependency supports several services.

| Field | Requirement | Approved definition |
| --- | --- | --- |
| Row ID | Calculated | Generate automatically. |
| Dependency Type | Conditionally required | Controlled category such as Customer, Supplier, Site, Technology, Utility, Transport, Regulatory, or Other. |
| Dependency Code | Conditionally required | Neutral identifier such as SUP-01 or TECH-02; do not enter real names. |
| Service Code | Conditionally required | Critical service affected by the dependency. |
| Location Code | Conditional | Location affected, blank or ALL when enterprise-wide. |
| Service Capacity Dependent % | Optional sensitive | Exact percentage of service capacity relying on the dependency. |
| Dependency Impact Band | Conditionally required when percentage is blank | Low: under 20%; Moderate: 20–49%; High: 50–79%; Critical: 80–100% or service cannot operate. |
| Criticality | Conditionally required | Customer-approved Low, Moderate, High, or Critical classification. |
| Alternative Available | Conditionally required | Yes, Partial, or No. |
| Alternative Code | Optional sensitive | Neutral code only; no alternative supplier or system name. |
| Switch Time Days | Conditional | Required when an alternative exists. |
| Financial Exposure Band | Optional | Non-exact exposure category. |
| Exact Financial Exposure | Optional sensitive | Exact amount only after Finance and Security approval. |
| Evidence Reference | Optional | Neutral reference ID only; never embed contracts or confidential documents. |
| Row Status | Remove | Use help text instead of sample records. |

Do not request supplier or customer names, contract numbers or documents, hostnames, IP addresses, architecture details, facility addresses, security vulnerabilities, usernames, credentials, or access details.
